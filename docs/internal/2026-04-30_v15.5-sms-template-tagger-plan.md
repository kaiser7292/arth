## Why this exists

Artha parses SMS from ~20 hardcoded banks + 11 PSU banks (via v15 Phase 2 system templates). Any bank outside that set produces silently-unrecognised SMS that sit invisibly in `pending_sms` and never become expenses.

This feature lets users paste an SMS, tap-to-tag the amount / merchant / card / etc, and save a template. Next time a matching SMS arrives, it parses automatically. No code changes, no app update.

Turns every Artha user into a parser contributor.

### Step D — Backup support [~10 min]
File: `services/backup.ts`

`sms_template_patterns` is **NOT** in `BACKUP_TABLES` today (system templates are re-seeded from bundled JSON on install). User-authored templates NEED to travel with backups or user loses them on reinstall.

Options:
1. **Add conditional filter in BACKUP_TABLES**: include only rows WHERE `source='user'`. Clean but requires extending the export function.
2. **Add a new table** `user_sms_templates` separate from system. Over-engineering; violates DRY.
3. **Include whole table in BACKUP_TABLES**. On restore, system rows get INSERT OR IGNORE (no-op since seeded from JSON).

**Decision: Option 3**. Simplest. Reseed logic in `seedPublicData` uses `INSERT OR IGNORE` already so re-importing system rows is a no-op. User rows travel for free.

Add `sms_template_patterns` to `BACKUP_TABLES` in a level that depends on nothing (level 2, no FK refs).

```ts
function tokenize(body: string): Array<{ text: string; start: number; end: number }> {
  const tokens = [];
  let i = 0;
  while (i < body.length) {
    // skip whitespace
    while (i < body.length && /\s/.test(body[i])) i++;
    if (i >= body.length) break;
    const start = i;
    while (i < body.length && !/\s/.test(body[i])) i++;
    tokens.push({ text: body.slice(start, i), start, end: i });
  }
  return tokens;
}
```

### Detection logic (pure)

```ts
// services/min-balance.ts
export interface BreachedAccount {
  account: FinancialAccount;
  currentBalance: number;
  threshold: number;
  shortfall: number;  // threshold - currentBalance, always positive
}

export function detectBreaches(
  accounts: FinancialAccount[],
  balances: Record<string, number | null>,
): BreachedAccount[] {
  const result: BreachedAccount[] = [];
  for (const a of accounts) {
    if (a.account_type !== 'savings') continue;
    if (a.min_balance <= 0) continue; // feature off for this account
    const bal = balances[a.id];
    if (bal == null) continue; // no meaningful signal yet
    if (bal < a.min_balance) {
      result.push({
        account: a,
        currentBalance: bal,
        threshold: a.min_balance,
        shortfall: a.min_balance - bal,
      });
    }
  }
  return result;
}
```

### Acknowledgement (MMKV)

Key format: `min_balance_ack_${accountId}_${YYYY-MM}`. Boolean value.

```ts
// services/min-balance.ts (continued)
import { MMKV } from 'react-native-mmkv';
const ackStorage = new MMKV({ id: 'artha-min-balance-acks' });

export function isAcknowledged(accountId: string, month: string): boolean {
  return ackStorage.getBoolean(`min_balance_ack_${accountId}_${month}`) ?? false;
}

export function acknowledgeBreach(accountId: string, month: string): void {
  ackStorage.set(`min_balance_ack_${accountId}_${month}`, true);
}
```

Per-month ack auto-resets by virtue of the key changing.
